# Two-model long-video rollout

This note defines the public Holo4D continuation contract. It is deliberately
data- and checkpoint-free; provide the paths through the launcher environment.

## Stages

For each selected Syn4D case, the evaluator uses two 49-frame windows with a
shared temporal boundary:

- **Seed:** Wan2.1 T2V-14B plus the AB12 step-19500 Holo4D checkpoint. The
  input is the source video and camera/track condition only. The target video
  is retained only for evaluation and visualization; it is not an input
  condition. The generated final target frame is written to
  `seed/last_target.png`.
- **Continuation:** Wan2.1 I2V-14B-480P plus the native I2V checkpoint. The
  seed-generated `last_target.png` is loaded as `inference_input_image` and
  `use_target_image_condition` is enabled. The target latent is sampled from
  noise, so target RGB is never copied into the prediction.

The continuation starts at the seed window's final source time. The evaluator
records both source and target boundary frames, a contact sheet, and
`i2v_context.json`, which states the actual condition and confirms that it is
not the previous source frame. `checkpoint_provenance.json` in each stage
prevents accidental reuse of artifacts generated by another checkpoint.

## Model bundles

The seed model bundle contains T2V diffusion shards, the text encoder, and the
VAE. The continuation bundle contains I2V diffusion shards, the same text
encoder/VAE, and the I2V image encoder. The two pipelines are loaded
sequentially and released between stages to bound peak memory. If base
camera-control weights are not colocated with the model roots, pass explicit
`I2V_SEED_CAMERA_CONTROL_CHECKPOINT` and
`I2V_CONTINUATION_CAMERA_CONTROL_CHECKPOINT` values.

## Reproducibility knobs

The launcher defaults to 384x672x49, 25 denoising steps, CFG 1.0, sigma shift
5.0, and seed 42. `NUM_PAIRS`, `SELECTION_SEED`, `NUM_SHARDS`, `SHARD_INDEX`,
`FORCE_RERUN`, `CAPTURE_FINAL_LATENTS`, and the profiling variables can be
set without editing code. The case manifest and all stage metadata are saved
under `OUTPUT_DIR`.
